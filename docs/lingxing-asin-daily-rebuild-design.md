# 领星 ASIN 日粒度产品总览与库存规划重构方案

> **方案状态：已按最新业务口径修订，待确认后实施。** 本方案覆盖领星 ASIN 日粒度数据导入、父 ASIN 周度产品总览、单品详情子 ASIN 销量看板以及库存规划工作台；赛狐不在本轮实施范围，但保留标准化接入边界。

## 一、已确认的业务决策

| 决策项 | 已确认规则 |
|---|---|
| 领星数据源 | 当前领星产品总览上传入口改接用户提供的 **ASIN 日粒度产品表现表**，不再以旧父 ASIN 周度表作为新数据源 |
| 产品总览粒度 | **父 ASIN + 店铺 + 国家 + 自然周（周一至周日）** 汇总展示 |
| 库存计算粒度 | **ASIN + 店铺 + 国家 + 日期**；父 ASIN 只做跨子 ASIN 的展示汇总，不能分摊或复制库存 |
| 库存规划总库存 | `FBA 可售库存 + FBA 在途库存 + 人工维护本地库存` |
| 默认货期 | 生产货期 30 天 + 物流 30 天 + 缓冲 10 天 = **总货期 70 天** |
| 子 ASIN 变体 | 单产品详情页底部改为变体销量看板，可选择最近 1、2、3、4 个完整自然周 |
| 赛狐 | 用户后续提供新的赛狐文件后，再按同一标准化日快照契约接入；当前不以空数据替代领星数据 |

## 二、输入文件核验结论

用户提供的领星文件共 **2,842** 条数据行、**156** 个字段，覆盖 **2026-08-03 至 2026-08-09** 连续 7 日；每天均含 **406 个 ASIN** 和 **330 个父 ASIN**。文件具备 `日期`、`ASIN`、`父ASIN`、`店铺`、`国家`、`销量`、`FBA-可售`、`FBA-在途`、`FBA-计划入库`、`本地可用` 等关键列，足以建立日快照与 ASIN 维度库存的事实层。[1]

现有 Excel 解析器已映射绝大部分字段，但**未映射 `日期`**；当前数据库也只以 `week_start_date` 与 `week_end_date` 存储导入周期。因此，继续把该文件写入 `lingxing_product_weekly` 会丢失日粒度，无法可靠支持变体销量和连续三日断货规则。[2]

## 三、目标数据架构

### 3.1 事实层：标准化 ASIN 日快照

新增 `ops_asin_daily_snapshots` 作为模块三产品总览的唯一日粒度事实表。它不是新上传入口，而是对既有“产品总览上传”中领星日表的标准化落库结果。

| 字段组 | 关键字段 | 规则 |
|---|---|---|
| 归属与追溯 | `id`、`workspace_id`、`import_id`、`source_type`、`source_row_hash`、`user_id` | 每一行可追溯到上传批次和源行；`source_type` 当前为 `lingxing`，后续可为 `saihu` |
| 业务主键 | `report_date`、`asin`、`parent_asin`、`store_name`、`country` | 唯一约束：`workspace_id + source_type + report_date + asin + store_name + country` |
| 产品识别 | `msku`、`sku`、`title`、`product_name`、`brand`、`category_1/2/3`、`operator`、`created_time` | 均来自领星源表，供父级归并和变体追溯 |
| 销售事实 | `sales_qty`、`order_qty`、`sales_amount`、`net_sales_amount`、`order_profit`、`ad_spend`、`ad_sales`、`sessions_total` | 日汇总时可相加；比率类字段由汇总值重新计算，不平均原始百分比 |
| 库存事实 | `fba_available`、`fba_in_transit`、`fba_plan_inbound`、`fba_total`、`available_stock`、`fbm_available`、`awd_available`、`overseas_available`、`source_local_available` | 库存是每日时点值，产品/周汇总只能取指定日期的最新快照，不能跨日相加 |
| 数据质量 | `report_date`、`source_row_hash`、`is_valid`、`validation_reason`、`created_at` | 同日重复、ASIN 为空、父 ASIN 缺失、国家/店铺缺失均须在预览阶段给出可处理提示 |

旧 `lingxing_product_weekly` 进入**历史兼容只读**状态。产品总览新查询优先读取 `ops_asin_daily_snapshots`，只有当用户查看历史旧批次时才读取旧表，并明确标识“旧周度来源”。这样既不破坏历史页面，也不会让新日表再次失去日期语义。

### 3.2 决策层：人工本地库存与货期参数

| 表/对象 | 主粒度 | 关键字段 | 用途 |
|---|---|---|---|
| `ops_local_inventory_adjustments` | ASIN + 店铺 + 国家 | `manual_local_qty`、`effective_date`、`reason`、`status`、`confirmed_by`、`confirmed_at` | 人工维护本地库存；只影响库存规划，不回写领星上传事实；保留历史版本 |
| `ops_inventory_planning_parameters` | 工作空间默认 / 店铺站点 / ASIN | `production_days=30`、`shipping_days=30`、`buffer_days=10`、`target_cover_days`、`moq`、`pack_size` | 三级覆盖的规划参数；总货期由三项确定性求和 |
| `ops_replenishment_plans` | ASIN + 店铺 + 国家 | `planned_qty`、`order_date`、`estimated_available_date`、`status`、`confirmed_by` | 仅已确认计划才可作为未来供给进入库存预测日历 |
| `ops_inventory_planning_versions` | 规划批次/版本 | 源数据截至日、参数快照、人工本地库存版本、计算结果、确认人 | 支持人工审核、追溯、对比和重新确认 |

## 四、汇总与计算口径

### 4.1 产品总览：父 ASIN + 周

父 ASIN 周度汇总主键为：`parent_asin + store_name + country + week_start_date + week_end_date`。一周固定采用周一至周日；例如用户上传的 2026-08-03 至 2026-08-09 正好形成一个完整自然周。

| 指标类型 | 汇总方法 |
|---|---|
| 销量、订单、销售额、净销售额、订单利润、广告花费、广告销售额、点击、曝光 | 对该父 ASIN 下所有子 ASIN、该周所有日记录求和 |
| ACOS、CVR、利润率、CTR、退货率 | 以汇总后的分子/分母重新计算，禁止平均子 ASIN 或日快照的百分比 |
| FBA 可售、FBA 在途、计划入库、AWD、海外仓 | 取周截止日每个子 ASIN的最新快照后相加；禁止把 7 天库存快照相加 |
| 7 天日销 | 最近完整 7 天 `销量 ÷ 有效在售日数` |
| 30 天日销 | 最近 30 天 `销量 ÷ 有效在售日数`；缺少历史数据时返回覆盖日数与“样本不足”，不得以 7 天硬冒充 30 天 |
| 子 ASIN 数量 | 周截止日有效子 ASIN 去重计数 |

有效在售日定义为：`report_date >= 创建时间`，且该 ASIN 在产品总览日快照中存在；后续加入人工停售区间后，停售日期须从分母中扣除。没有可验证状态时，页面显示“在售状态待核对”，不隐藏数据缺口。

### 4.2 单产品详情：子 ASIN 变体销量看板

现有详情页底部的“子ASIN变体”静态表将替换为以下字段，不再将没有业务价值的空标题列作为主要展示项。

| 区域 | 内容 |
|---|---|
| 周期控制 | 单选：最近 1 周、2 周、3 周、4 周；仅计算完整自然周，显示明确起止日期 |
| 识别列 | 子 ASIN、MSKU、SKU、变体标题/品名（若源数据存在） |
| 销量列 | 所选周期销量、日均销量、相对上一等长周期的环比、销量趋势迷你柱图 |
| 库存列 | 截止日 FBA 可售、FBA 在途、人工本地库存、规划总库存、数据截至日 |
| 经营辅助列 | 所选周期销售额、订单利润、ACOS；价格仅作为可选展开列 |
| 明细操作 | 查看日销明细、编辑本地库存、进入该 ASIN 的库存规划详情 |

变体销量接口的输入为 `parentAsin`、`storeName`、`country`、`weeks=1|2|3|4`；输出必须同时携带所选周范围、数据截至日、有效在售日数和每个 ASIN 的最新库存时点，避免前台自行拼接或重复计算。

### 4.3 库存规划：ASIN 维度

```text
规划总库存 = FBA-可售 + FBA-在途 + 已确认人工本地库存
总货期 = 生产30天 + 物流30天 + 缓冲10天 = 70天
加权日销 = 日销7 × 50% + 日销30 × 50%
最终日销 = 已确认人工调整日销；没有调整时为加权日销
```

`FBA-计划入库`、AWD 和海外仓仍需保留为事实明细，但不自动计入规划总库存。只有用户登记为已确认的补货/调拨计划，并给出预计可售日后，才在该日之后进入预测库存，避免把尚未可售的货源提前抵扣。

对于“库存为 0 连续 3 天没有销量”的断货规则，日表已使规则可实施。判定的观察单位是 **ASIN + 店铺 + 国家**：若连续 3 个完整报告日的 `FBA-可售 + FBA-在途 + 同期生效人工本地库存 = 0` 且 `销量 = 0`，标记为“已确认总库存断货”。若只有 FBA 可售为 0 但在途或本地库存大于 0，则标记为“渠道缺货风险”，不混同于总库存断货。

人工本地库存必须保存有效日期；在人工库存尚未建立历史记录的过往日期，系统不得把当前人工值反向填入历史三日断货判断，而应标记为“本地库存历史待核对”。

## 五、替代范围与非目标

| 现有内容 | 新方案处理 |
|---|---|
| 旧领星父 ASIN 周度上传解析 | 新文件上传后停止作为当前产品总览来源；保留历史只读查看 |
| 产品总览 | 改为父 ASIN 周度汇总，基于 ASIN 日快照计算 |
| 单品详情底部变体表 | 改为可选 1–4 周的子 ASIN 变体销量与库存看板 |
| 旧库存预警中心 | 完全替换为 ASIN 维度库存规划工作台 |
| AI 补货预测 | 不再作为库存计算来源；若保留，仅可解释已确认的确定性结果 |
| 赛狐 | 本轮不导入、不模拟；后续按 `ops_asin_daily_snapshots` 同一契约映射 |

## 六、页面结构与人工确认闭环

### 6.1 产品总览

产品总览保留现有产品卡片、运营负责人批量分配、站点/店铺筛选和产品详情入口，但其显示单位统一为父 ASIN 周汇总。顶部新增“当前数据截至日”和“最近完整周”标识；周切换最多显示最近 4 个完整自然周，并明确每一周的起止日期。

| 页面区域 | 展示与交互 |
|---|---|
| 数据状态栏 | 数据来源“领星 ASIN 日表”、数据截至日、最新完整周、导入批次状态、异常行数量；只读显示，不创建第二上传入口 |
| 父 ASIN 卡片头部 | 产品名、父 ASIN、店铺、国家、运营负责人、子 ASIN 数量、最近周销量/销售额/利润、数据质量标签 |
| 周度矩阵 | 最近 1–4 周的销量、销售额、利润、广告费、ACOS、CVR、退货率；切换周期后更新矩阵，不丢失父 ASIN 维度 |
| 库存摘要 | 周截止日 FBA 可售、FBA 在途、已确认本地库存、规划总库存、7/30 天日销、计划状态；库存列提供“查看 ASIN 明细”而非直接把父级值误分配给子 ASIN |
| 批量动作 | 运营负责人分配、进入库存规划、导出当前筛选结果；禁止批量自动下单 |

### 6.2 单产品详情的子 ASIN 变体销量看板

截图中的静态“子ASIN / SKU / 标题 / 价格”表替换为可审计的销量看板。它固定放在数据看板底部，满足用户所述“单产品详情页的数据看板最下方”位置。

```text
[子 ASIN 变体销量与库存]                     [最近 1 周 ▾]
数据范围：2026-08-03 至 2026-08-09 · 周截止日库存：2026-08-09
┌──────────┬────────┬────────┬────────┬────────┬────────┬──────────┬──────────┬────────┐
│ 子 ASIN  │ MSKU   │ SKU    │ 周销量 │ 日均销 │ 环比   │ FBA可售  │ 在途     │ 本地库存 │
├──────────┼────────┼────────┼────────┼────────┼────────┼──────────┼──────────┼────────┤
│ ...      │ ...    │ ...    │ ...    │ ...    │ ↑/↓    │ ...      │ ...      │ 人工确认 │
└──────────┴────────┴────────┴────────┴────────┴────────┴──────────┴──────────┴────────┘
```

用户切换最近 1、2、3、4 周时，系统同时更新销量、日均销量、环比和有效在售日数。库存始终使用所选期间最后一个完整周截止日的 ASIN 快照；如果该 ASIN 在截止日没有快照，必须显示“库存快照缺失”，不得用父 ASIN 值补齐。

### 6.3 库存规划工作台

`/ops/inventory` 路径保留，但现有“库存预警中心”页面整体替换为“库存规划工作台”。页面默认以 ASIN 为行、父 ASIN 为可折叠分组，不再以旧 SKU 预警和 AI 预测任务为计算依据。

| 区块 | 内容与人工控制 |
|---|---|
| 顶部决策栏 | 数据截至日、默认总货期 70 天、需要订货/断货/数据待核对数量，以及“刷新产品总览数据”入口 |
| 筛选与批量区 | 店铺、国家、运营、父 ASIN、风险状态、是否存在人工调整；批量导出与批量“提交确认”，不包含自动采购 |
| ASIN 规划表 | FBA 可售、FBA 在途、已确认本地库存、规划总库存、7/30 日销、最终日销、总货期、预计断货日、建议下单日、建议量、状态与数据质量 |
| 明细抽屉 | 7/30 日销量日历、三日断货证据、本地库存编辑历史、货期参数、补货计划、计算公式、版本差异和人工备注 |
| 参数中心 | 工作空间默认值 30/30/10；店铺站点和 ASIN 覆盖；所有覆盖均显示继承来源和生效时间 |
| 确认版本 | 用户确认后冻结源数据时点、人工本地库存、参数、日销调整与计算结果；后续新导入或修改自动标记“需重新确认” |

人工编辑遵循“AI 是助手，人是决策者”：用户可调整日销量、手工录入本地库存、编辑货期或补货计划；系统在保存前展示受影响的订货日期与建议量差异。AI 如被启用，只在冻结版本上解释风险、列出待核对项，不能改变数量、状态或确认结果。

## 七、实施顺序与验收门槛

| 阶段 | 工作内容 | 验收标准 |
|---|---|---|
| 1 | 新增日快照与决策层表、索引和迁移 | 领星 `日期` 不丢失；同日同 ASIN 同店铺同国家不能重复；迁移先执行再发布 |
| 2 | 更新领星导入解析、预览校验和批次替代逻辑 | 此文件可预览并完整映射；不新增上传入口；替代操作不物理删除可追溯历史 |
| 3 | 重写父 ASIN 周汇总与单品详情查询 | 330 个父 ASIN与 406 个 ASIN可按周正确聚合；库存不跨日相加 |
| 4 | 重构变体销量看板 | 1–4 周选择切换正确；销量与最新 ASIN 库存可追溯到报告日期 |
| 5 | 实施库存规划和人工本地库存审核 | 默认总货期显示 70 天；本地库存可编辑、确认、追溯；断货只在三日证据完整时标记 |
| 6 | 测试与上线 | 补充导入、聚合、库存去重、三日断货、参数覆盖、人工库存版本的 Vitest；通过类型检查和真实样本回归 |
