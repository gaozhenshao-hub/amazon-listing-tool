# Product Spec：模块三领星 ASIN 日粒度产品总览与库存规划

## 1. 产品概述

模块三服务于亚马逊运营人员的产品经营分析与补货决策。当前领星周度数据和旧库存预警无法支持 ASIN 日粒度库存追溯、变体销量观察与可审核的补货规划。本迭代以领星MCP父ASIN周报作为当前周度权威事实，以ASIN日快照支撑详情与库存规划，并保留ERP上传的历史来源；前台将所有来源整合为一套父ASIN产品总览和一套产品详情，而非按来源分裂为两套页面。

系统的原则是：**AI 可以解释，不可以替用户下结论或下单；所有计算输入、人工修订和确认结果必须可编辑、可追溯。**

## 2. P0 核心功能

| 功能 | 已确认行为 |
|---|---|
| 领星日表导入 | 使用既有产品总览上传入口读取 `产品表现ASIN` 日粒度表；不创建重复上传入口；写入可追溯批次和标准化 ASIN 日快照 |
| 产品总览 | 按父 ASIN、店铺、国家、自然周汇总；近四个完整自然周可比较；库存展示由 ASIN 截止日快照汇总而来 |
| 产品详情 | 数据看板最下方展示子 ASIN 变体销量与库存；用户可切换最近 1–4 个完整自然周 |
| 统一产品视图 | 前台只保留一个产品总览与一个详情入口，以`父ASIN+店铺+国家`归并；周度经营指标优先MCP父ASIN周报，子ASIN销量/利润/广告/库存取同身份日快照，ERP历史仅作来源化参考且不得与MCP同口径数值相加 |
| 库存规划 | 完全替换旧库存预警；以 ASIN、店铺、国家为规划行；计算总库存、加权日销、建议下单日和建议量 |
| 默认货期 | 生产 30 天、物流 30 天、缓冲 10 天，总货期 70 天；支持工作空间、店铺站点、ASIN 三级覆盖 |
| 本地库存 | 用户手工维护本地库存，须保留生效日期、修改原因、确认人和版本历史 |
| 断货 | 连续 3 个完整报告日中，规划总库存为 0 且销量为 0，才标记“已确认总库存断货” |

## 3. 用户流

运营人员在既有产品总览入口上传领星 ASIN 日表，并先在预览中核对日期、ASIN、父 ASIN、店铺、国家和库存字段。确认导入后，系统在后台生成 ASIN 日快照和父 ASIN 周汇总。用户在**同一产品总览**按父ASIN、店铺、国家浏览近四周经营表现与数据覆盖状态，进入**同一产品详情**后查看各子ASIN在1–4周内的销量、利润、广告和截止日库存。若MCP或ERP来源未覆盖某字段，系统明确显示“未提供”，不补零或跨来源加总。

运营人员进入库存规划工作台，先核对默认货期与数据截至日，再按 ASIN 填写或更新本地库存、需要冲量时的人工日销量、参数覆盖和补货计划。系统即时显示计算依据及建议变化；用户确认后，系统冻结本次输入与计算结果为规划版本。后续数据导入或人工调整会提示该版本需要重新确认。

## 4. AI 能力边界

本迭代不将 AI 用作日销、库存或补货量的事实来源。若启用 AI，它只能根据已冻结的库存规划版本输出风险解释、数据缺口、异常变化和需人工核对的事项；AI 输出必须结构化、可编辑，不能自动改写库存、日销量、订货日期、补货量或确认状态。

## 5. 数据模型

| 实体 | 粒度 | 关系 |
|---|---|---|
| ASIN 日快照 | ASIN + 店铺 + 国家 + 报告日 | 归属一条导入批次；归并到父 ASIN 周汇总 |
| 统一产品视图 | 父ASIN + 店铺 + 国家 | 查询层的来源化归并结果；关联MCP周报、ERP历史、日快照和可选人工产品主档，但不改写原始事实 |
| 本地库存调整 | ASIN + 店铺 + 国家 + 生效日 | 独立于领星源数据；参与规划库存计算 |
| 库存参数 | 工作空间/店铺站点/ASIN | 参数按优先级覆盖，快照进规划版本 |
| 补货计划 | ASIN + 店铺 + 国家 | 已确认且有预计可售日时才进入预测供给 |
| 库存规划版本 | 一次计算确认 | 固化源数据截至日、参数、本地库存、日销调整和输出 |

## 6. 非功能要求

导入与查询必须按工作空间隔离；源数据和人工数据均可追溯到批次或版本。库存快照禁止跨日累加，百分比禁止简单平均。导入、汇总与计算必须有明确的空数据、样本不足、重复数据和状态异常提示。MCP、ERP、日快照的相同口径指标不得自动累计；跨店铺、站点的同ASIN不得按裸ASIN合并。数据库迁移必须先执行，再发布依赖代码；所有计算函数、来源优先级和导入映射均需 Vitest 覆盖。
