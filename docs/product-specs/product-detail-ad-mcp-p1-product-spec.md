# 产品规格：产品详情广告 MCP 自动录入 P1

**版本：** 1.0  
**日期：** 2026-09-10  
**状态：** 已确认，待实施

## 1. 目标与范围

本功能将领星广告数据作为**独立、可追溯的日事实**保存，并在统一产品详情中按与产品总览相同的完整自然周展示。系统只在来源范围完整、身份可解析且映射无歧义时自动应用；异常运行保持失败关闭，并进入可编辑的复核队列。用户不需要为正常广告数据执行人工“诊断”或确认。

P1 只使用以下三类已核验报告：广告授权店铺（`ad_auth_shops`）、广告商品报告（`ad_campaign_product_report`）与广告活动报告（`ad_campaign_report`）。不读取或展示搜索词、关键词、投放目标、广告组或组合报告；这些是独立分析场景，不参与本期产品详情或产品总览周度指标。

| 能力 | P1 行为 | 不在 P1 的行为 |
| --- | --- | --- |
| 广告账户关联 | 将广告 Profile 精确关联到工作空间内的店铺 SID 与规范站点。 | 基于店铺名、活动名或模糊文本猜测关联。 |
| 广告商品事实 | 以广告商品 ASIN 为主、唯一 SKU 为回退，保存每日广告表现及活动关系。 | 将活动级金额复制或分摊到多个商品。 |
| 父 ASIN 归属 | 以 `工作空间 × SID × 站点 × 子ASIN` 唯一回溯现有日快照的父 ASIN。 | 用名称、标题或活动名称推断父 ASIN。 |
| 自动应用 | 正常完整日批次直接写入；同源迟到归因按修订写入并留审计。 | 覆盖不同来源、不同 Profile 或不同业务日的事实。 |
| 产品详情 | 仅展示完整自然周广告商品 KPI 与活动辅助信息。 | 搜索词、关键词、投放目标、旧 30 天广告概览作为权威来源。 |

## 2. 用户与关键流程

运营人员在产品总览选择某个父 ASIN、店铺和站点后进入统一产品详情。页面默认选择最近一个完整自然周，读取该周的广告商品事实，并按同一父 ASIN 的所有已映射子 ASIN累计可加指标；活动事实只显示活动状态、预算与活动级辅助信息。系统明确显示周起止日、来源、数据完整性和映射覆盖率。

后台每天北京时间 18:00 对每个已启用广告 Profile 串行读取前一报告日。系统先读取授权店铺目录，再按单 Profile、单日分页读取广告商品和活动报告。通过完整性校验的日窗口直接应用。任一 Profile 映射歧义、分页截断、不可识别总计行、非有限指标或来源窗口失败都会使相应运行进入复核，不写入该异常窗口的广告事实。

## 3. 领域模型与事实边界

广告日事实与 `ops_asin_daily_snapshots` 分层保存。后者继续保存产品表现、库存与领星日表现中的广告聚合字段；本期新表保存广告账户、广告商品和活动的可追溯明细。产品详情不能将两类来源的广告花费、销售或订单相加，以避免双重累计。

| 实体 | 粒度 | 主身份 | 用途 |
| --- | --- | --- | --- |
| 广告 Profile 映射 | 工作空间 × Profile | `workspaceId × profileId` | 将 Profile 精确映射到 `sourceStoreId × country`。 |
| 广告商品日事实 | 工作空间 × Profile × 报告日 × 广告商品实体 | `workspaceId × profileId × reportDate × adType × campaignId × adGroupId × advertisedAsin × advertisedSku` | 产品详情 KPI 的唯一广告来源。 |
| 广告活动日事实 | 工作空间 × Profile × 报告日 × 活动 | `workspaceId × profileId × reportDate × adType × campaignId` | 状态、预算与活动级辅助信息。 |
| 受治理同步批次 | 工作空间 × 数据域 × 运行窗口 | 复用 `ops_external_sync_batches` 与行级草稿。 | 保存范围、原始响应哈希、Run/Trace、校验与应用审计。 |

## 4. 自动写入门禁

| 门禁 | 正常处理 | 异常处理 |
| --- | --- | --- |
| Profile 映射 | Profile 唯一映射到 SID 与站点，自动更新目录。 | 整个 Profile 日窗口待复核。 |
| 分页与覆盖 | 全部页完成，实体行计数与来源元数据一致。 | 不写入该窗口，保存批次错误摘要。 |
| 总计行 | 仅过滤可识别的空实体总计行。 | 形态变化或非空总计行待复核。 |
| 广告商品身份 | 必须存在合法的活动、广告类型、广告商品 ASIN 或唯一回退 SKU。 | 无法识别行保留草稿证据，不计入 KPI。 |
| 父 ASIN 映射 | 子 ASIN 唯一回溯至父 ASIN。 | 未映射或多映射行不猜测，保留映射异常。 |
| 指标与修订 | 非负、有限并通过合理波动校验；同源修订保留新版本与批次审计。 | 不写入异常批次或异常行。 |
| 周完整性 | 周内7个日期、纳入 Profile 均成功且无截断。 | 页面显示“待复核/部分数据”，不作为正式周度 KPI。 |

## 5. 数据展示合同

产品详情广告区的数据身份必须是：

> `父ASIN × sourceStoreId × 规范站点 × 周一至周日`

可加指标包括广告花费、广告销售额、广告订单、展示、点击和转化归因指标。比率指标必须由周度汇总后的分子分母重新计算；例如 ACoS 为周广告花费/周广告销售额，CTR 为周点击/周展示，CPC 为周广告花费/周点击。活动级数据仅作为辅助列表，不能与商品 KPI 相加。

## 6. 安全、审计与权限

所有广告读取均通过现有受治理的领星只读能力，串行执行并遵守 QPS=1。每次运行复用现有 Job/Run/Trace 与 `ops_external_sync_batches` 审计，保存范围、来源哈希、归一化版本、校验摘要、操作者与应用时间。P1 不包含对亚马逊广告的写操作，不执行预算、竞价、否词、活动状态或投放设置变更。

只有具备运营管理权限的用户可以查看异常复核和运行摘要。普通产品详情用户只读取已应用事实和脱敏的覆盖状态。无论角色如何，页面不展示 MCP 凭据或原始访问令牌。

## 7. 验收标准

| 场景 | 通过条件 |
| --- | --- |
| 正常日读取 | 一个 Profile 的广告商品与活动报告分页完整、映射唯一时，自动应用并写入 Run/Trace、批次与事实审计。 |
| 异常日读取 | Profile 映射歧义或任一报告截断时，不写入该窗口事实，并显示可解释复核原因。 |
| 同源修订 | 同一事实身份的新来源哈希不同，当前事实更新且可回溯至旧批次与新批次；不累计双份指标。 |
| 父 ASIN周度读取 | 父 ASIN详情只汇总已映射子 ASIN、同店铺、同站点、同一完整自然周的广告商品事实。 |
| 双重计数防护 | 广告商品 KPI 不与 `ops_asin_daily_snapshots` 的广告聚合字段相加；活动级指标不分摊至商品。 |
| 范围保护 | 搜索词、关键词、投放目标与广告组报告不被 P1 的读取、存储或产品详情查询调用。 |
