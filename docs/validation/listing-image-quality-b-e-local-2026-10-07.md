**更新：2026-10-08｜状态：已完成开发库验证、青岛生产增量迁移与应用发布。**

本记录对应已批准的《青岛独立站-Listing与图片建议质量优化详细实施方案》。阶段 A 的既有防绕行修复此前已本地封存；本次将阶段 B–E 的代码、0204–0207 增量表及运行时工件发布到青岛独立站。所有迁移均为**新增表/索引**，没有回填、重跑历史 Listing、覆盖人工内容，亦未触发模型、Provider、采集或历史批量任务。

同时治理了旧下载与出库路径：Listing 未审报告、浏览器 CSV/HTML 导出、旧 Artifact 指针切换以及未审五点直写均不可达；视频脚本、产品开发测试表、运营模板与图片成果下载均要求工作空间范围及超管权限。Listing 富文本描述统一以 DOMPurify 白名单安全渲染，避免历史人工/AI 字符串在预览页执行脚本。

## 验收证据

### 代码与离线验证

- **全仓隔离回归：**以 `env -u DATABASE_URL ALLOW_REAL_NETWORK_IN_TESTS=0 RUN_REAL_DB_TESTS=0 RUN_REAL_LLM_TESTS=0` 执行，**536 个文件通过、3 个跳过；4,869 项通过、14 项跳过，零失败**。此前 15 个失败文件均已按现行受控采集、版本化 Schema、受控出网、工作空间谓词和 Skill 回放/灰度计量合同完成修复或退役替换。
- **构建质量：**全站 TypeScript 为 0 诊断；客户端运行时标识符门禁、改动文件 ESLint、`pnpm build` 与 Bundle 预算通过。Vite 对少量惰性块超过 500 kB 仍给出警告，但构建成功；最大块约 0.87 MB。
- **真实开发库验证：**0206/0207 先在受管 WebDev 开发库经环境、显式开关和目标 Schema 三重门禁执行。对可清理夹具验证了 Step0→1 确认、重读、Step0 重确认使 Step1 失效及可信 PNG 回执写入；所有夹具复核后清零。

### 青岛生产迁移与发布（2026-10-08）

1. **生产预检：**目标为受控青岛生产 Schema，迁移账本和 0204–0207 目标表在执行前均为缺失状态；应用三服务均为 `active`，本机健康与登录入口均为 200。
2. **受控迁移：**通过显式生产开关、`NODE_ENV=production`、目标 Schema 和数据库锁门禁，顺序执行 **0204、0205、0206、0207**。迁移账本四项成功，新增治理表可见；迁移后无治理业务记录、无历史回填。
3. **运行时预演：**发现旧生产运行时不含完整依赖树，特别是 `sharp`；未在现网直接安装。改以独立候选目录冻结安装依赖，并在**同一生产环境键名**下以 `AUTH_MODE=local` 启动候选 Web。候选首页与 `/login` 均为 200。日志中的 OAuth 初始化提示不影响独立账号密码路径。
4. **原子切换：**将候选 `dist`、`package.json` 和已验证依赖树原子置换到应用目录；旧 `dist`、依赖与清单保存在版本化私有回退目录。切换脚本包含服务/HTTP 任一失败即自动恢复旧工件的保护。
5. **上线结果：**旧入口 `index.js` SHA-256 为 `ef083e00…488a4`，新入口为 `4152c026…7ccf8`，应用目录已实际使用新哈希。`amazon-listing-web`、`amazon-listing-worker`、`amazon-listing-scheduler` 均为 `active`；本机 `/health` 和 `/login` 为 200；切换后的三服务错误级日志计数为 0。
6. **浏览器静态验收：**生产登录入口正常显示独立“邮箱/手机号 + 密码”登录表单。Sandbox 浏览器与已恢复的 **My Browser** 均可加载该页；My Browser 本次导航未再返回 504。未提交任何登录表单，也未创建业务、模型或 Provider 任务。
