# 智能图片建议创建采集任务内部错误：诊断与修复记录（2026-09-14）

## 用户症状

在智能图片建议 Step 0 的“受控采集与竞品研究对象”区域输入美国站 ASIN 并点击“创建采集任务”后，页面显示“系统内部错误”。前端调用的是 `acquisition.createJob`，参数限定为图片工作流消费者、美国站、基础信息与图片能力，以及单次费用上限；该动作本身不直接执行外部 Provider 请求。

## 代码级根因

任务创建服务先前只查询状态为 `active` 的采集 Provider Profile。只要 Profile 尚未配置、仍处于 `qualification_pending`、已暂停或被拒绝，查询即返回空值；服务随后抛出普通 `Error`。生产环境的统一错误格式会将普通异常隐藏为“系统内部错误”，因此用户无法识别实际的安全门禁。

该路径是**失败关闭**行为，但错误合同错误地将业务预条件伪装成内部故障。生产日志仍将在无迁移发布后按请求ID核验；在此之前，不将任何单一Provider状态或数据库异常误记为最终生产根因。

## 最小修复

`startAmazonAcquisitionJob` 现改为读取当前采集 Provider Profile，并对以下预条件分别返回结构化的 `PRECONDITION_FAILED`（HTTP 412）提示：

| 前置条件 | 用户可见提示 | 安全行为 |
|---|---|---|
| 未配置Profile | 指向采集任务中心的Provider治理设置 | 不创建Job、不入队 |
| Profile未启用 | 指向资格审核和“启用”操作 | 不创建Job、不入队 |
| 受控Apify密钥缺失 | 指向系统设置的API连接管理 | 不创建Job、不入队 |
| 预算未配置 | 指向Provider治理预算设置 | 不创建Job、不入队 |

修复不改变任何资格结论，不自动启用Provider，不读取或返回密钥，也不恢复旧HTML爬虫。它同样不创建新的Apify Run、关键词任务或Heartbeat。

## 本地验证

新增纯Mock回归覆盖“Profile缺失”和“Profile仍待资格”两种场景，均确认不会持久化Job、不会入队AI Job，并且tRPC转换后仍保留可读的预条件失败信息。定向4项Vitest与涉及文件ESLint通过；定向TypeScript检查确认本轮文件新增诊断为0。全局TypeScript仍有已记录的152项历史诊断，本次未引入新的相关诊断。生产构建与Bundle预算检查通过。

## 待生产复验

待用户单独确认无迁移发布后，将以版本化备份、原子替换和三服务健康检查发布本修复。发布后的首次界面操作仅用于验证错误合同；除非用户另行给出明确的外部调用与费用授权，Provider Profile将不被启用，也不得实际发起采集。
