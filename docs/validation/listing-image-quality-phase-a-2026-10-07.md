# Listing 与图片建议质量治理 · 阶段 A（本地）

**范围：**按已确认的详细实施方案先完成合同冻结与快速止损；本轮文档不构成青岛发布或历史数据重跑的证明。

## 关键合同

1. Listing 标题自检的唯一维度来源是 `LISTING_CHECKLIST_DIMENSIONS.title`，标题 Prompt 的 JSON 示例必须与解析器对齐；多件/套装的信息仅在已有产品事实支撑时进入内容覆盖检查，不生成未证数量。空数组、缺维度及失败项缺原因/建议拒绝持久化。
2. `listing.bullet.step.generate` 的逐条生成与优化明确携带 `quality_first`；皇帝 Skill Run 记录真实模型与回退，候选视图展示实际模型；只有预设且没有实际运行记录时不声称已由特定模型生成。原有事实过滤和人工确认边界保留。
3. 图片工作流的 `approved_deliverable` 是独立于在线预览的业务成果出口：服务端只允许超级管理员在**当前授权工作空间**导出已确认的 Step 0 竞品研究＋Step 1–6 六个制作阶段，逐阶段核实确认态和实际人工正文。Step 0 可兼容已人工确认但未另存编辑的综合结论；其他步骤不得回退 AI 草稿。旧设计师裸图未做来源/用途核实则拒绝成果导出；未分类图片 URL 不进入导出包；历史资料保持站内查看。
4. 旧版 Step 5 HTML/PDF 浏览器本地生成按钮移除，直接请求 `getExportBundle`/`exportPdf` 同样无法绕过权限/确认；Step 5 变化后撤销旧 Step 6 确认。当前只定义“已确认业务成果”的下载，不将其误称管理员全量归档；后续独立的 `admin_full_archive` 必须显著保留草稿/过期标签并走超管授权。
5. 图片裸URL直接充当本品设计师素材、Step 4附件的旧入口在不破坏合法上传的前提下受控失败关闭；后续阶段C须建设持久的资产身份、来源/用途许可、哈希和历史归类。竞品图片仅供内部研究，绝不作为我方制作素材。
6. 图片上传额外通过 Sharp 解码像素、校验格式/宽高/像素/动画帧数及20MB限制；仅有PNG头的截断文件也会被拒绝。旧竞品 tRPC base64 入口同样先验字节再存为研究图。**生产部署新增原生依赖 `sharp`，只有在青岛构建/依赖预检与发布授权后才能上线**，不能仅复制新 dist 使用旧 node_modules。
7. 图片项目/会话的所有路由按当前工作空间复验；遗留未绑定项目仅创建者可读。竞品图片更新与删除在仓储层使用 `(imageId, projectId)` 联合条件。Step0–3重确认时如果内容变化，同一会话写入中撤销下游确认位，不能直接调用 API 保留旧成果资格。

## 可见行为

- 运营人员继续在线预览和编辑，导出按钮仅超管在 Step 6 已确认时出现；服务端会进一步拒绝任一确认缺失/旧裸素材，并显示可操作原因。
- 导出显示“**竞品研究＋六个制作阶段**”，共七个栏目；不删减 Step 0 或 Step 6 来迎合旧版六列测试。
- 新版单条卖点候选显示实际模型、质量优先预设和回退次数；人工改写后明确显示需要重新自检。历史旧候选缺运行元数据时标记“未记录”，不推断为 GPT‑6 Astra。

## 验收与边界

- 18个离线回归文件、196项测试已通过：包含真实tRPC/Express路由、工作空间与竞品图片归属、上游重确认、四种实际解码图片和截断PNG，以及Listing质量优先路由、自检维度、图片与产品开发导出权限。没有发出模型/Provider调用。
- 改动文件零警告ESLint、全量TypeScript、客户端标识符门禁与正式构建均通过；Bundle预算通过（入口约0.55MB，最大惰性富文本Chunk约0.86MB）。Vite仍报告部分大Chunk提示，不能宣称“完全无构建警告”。构建第一次因终端大量输出中止，重定向日志后完整构建退出码为0。
- **范围未闭环：**目前已修图片建议两条成果接口与产品开发三项下载API；站内另有多处基于浏览器Blob/URL的本地数据下载及后台导出，尚未逐项改为仅超管、也未建设 `admin_full_archive`。因此不能称“全系统所有导出已受控”，此项必须在后续阶段闭环并单独验收。
- 阶段B的事实/核心/候选不可变版本与持久化人审、阶段C的资产登记、阶段D的依赖哈希及完整下载审计、阶段E的真实模型/人工盲审**尚未在阶段A实现**。生产迁移、Skill更新、发布及额外模型/Provider调用须另行获得对应授权；现有真实Listing与图片工作流不自动重跑。

## 独立复审后本地补丁（尚未发布）

- 旧 `exportPdf` 入口与完整成果包使用同一 Step0–6 人工确认门禁；Step6 未确认无法从旧 PDF 接口绕开。
- 由于旧知识库图片尚无可验证的本品制作用途身份，Step4 与 Step5 的相关模型输入和已确认成果下载暂时失败关闭；图片仍保留在站内供研究、查看与人工移除，不能将可读权限当作制作许可。待阶段C可信来源/用途账本接通后再按用途恢复。
- Step2 A+子模块锁定不能在大纲已确认后静默改变上游内容；阶段A的 Step0–3 下游失效规则继续生效。
- 针对旧PDF、知识库参考图、Step2重确认的三份真实tRPC路由测试及相关改动的零警告Lint复验通过。阶段B的0204与阶段C的0205**仅在隔离开发库**执行，生产仍运行旧代码和旧Schema。
