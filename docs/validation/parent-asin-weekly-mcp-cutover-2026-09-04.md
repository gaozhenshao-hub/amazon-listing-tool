# 父ASIN周报MCP切换验收记录

## 目标与生效口径

本次将产品总览的自动周度数据来源由“ASIN日快照聚合”切换为领星MCP的**父ASIN、自然周**产品表现报表。ASIN日数据不再生成或覆盖产品总览父ASIN周度指标，而继续由单ASIN详情和库存规划使用。历史上传周表和既有内部日聚合周事实均保留，不删除、不覆盖，并按同一店铺、站点、父ASIN、自然周的身份规则与新MCP周报隔离。

| 消费场景 | 生效来源 | 处理规则 |
| --- | --- | --- |
| 产品总览的系统周度页签 | 领星MCP父ASIN自然周报 | 同身份同周优先使用MCP周报，不和其他来源累计 |
| 产品总览的ERP页签 | 用户上传的父ASIN周表 | 保留为历史/人工导入参考，不被删除 |
| 单ASIN详情 | ASIN日快照 | `getLingxingDailyVariants`继续独立展示子ASIN日粒度销量与库存 |
| 库存规划 | ASIN日快照与库存快照 | 继续使用子ASIN日销、可售/在途等指标 |

## 受治理周报任务

父ASIN周报任务通过领星MCP的产品表现读取能力调用，固定使用`date_view_type=week`、`summary_field=parent_asin`和完整自然周范围。读取覆盖全部已授权美国站店铺，逐店分页并保留1QPS、Trace、原始响应归档和失败关闭规则。

旧`parent_asin_weekly_rollup`日快照聚合任务已停用。当前仅保留`parent_asin_weekly_mcp`这一条周度自动任务，计划为UTC周一08:10，即北京时间周一16:10。该周任务使用受限UTC周一计时器，避免星期Cron的已知下次运行计算缺陷；完整性校验通过后直接、幂等且可审计地应用，任何店铺覆盖不足、分页截断、异常行或非完整自然周都会阻断写入。

## 首次周报预览与写入验证

首次只读预览使用2026-08-24至2026-08-30自然周和全部已授权美国站范围。领星新版MCP协议的`search → action`适配曾因缺少`toolVersionId`且把对象参数错误封装为`paramsJson`导致店铺目录为空；现已改为传递Schema中的版本标识和对象化参数。修复后预览完成，读取337条父ASIN周报记录，未出现失败窗口、分页截断或待复核行。

经用户确认的首次应用仅复用该已完整预览批次，不发起第二次MCP读取。应用创建1条可追溯导入记录与337条`lingxing_mcp_parent_asin_weekly`来源事实；同来源相同内容会幂等跳过，不同内容会冲突阻断，且不会覆盖上传或`internal_daily_rollup`历史事实。

初次审计误将历史兼容字段`storeName`、`parentAsin`和`weekStartDate`用于核验，因此显示为空。实际Drizzle写入和产品总览查询使用的是`store_name`、`parent_asin`、`week_start_date`及`week_end_date`。按真实字段重新审计后，337条新来源事实的店铺、站点、父ASIN和周起止字段均完整，337个身份均唯一，来源批次与Trace均可追溯；未发现数据损坏。为保护下一自然窗口曾短暂停用该周任务，纠正后已恢复同一条计划，未创建第二触发器、未重放或更改事实。

## 历史周表对账

对同一自然周的脱敏身份和核心指标聚合对账显示，MCP周报有337条记录，历史上传周表有463条记录；其中333条身份重合、4条仅存在于MCP来源。身份重合记录中，226条核心指标一致、107条存在差异。该差异保留在各自来源事实中，产品总览系统周度页签按已确认规则优先显示MCP周报，ERP页签继续保留上传周表视图，未以任一来源静默覆盖另一来源。

> 指标差异的成因需要在后续业务复核时结合领星导出时间、结算/退款回补和上传周期确认；本次没有基于差异修正、删除或重写任一历史数据源。
