# 高质量 Skill 全量提示词与路由治理修复

**日期：** 2026-09-20  
**范围：** 皇帝 AI 中台内已发布的 80 个“高质量要求”或高影响 Skill。  
**变更类型：** 无数据库结构迁移；发布包部署后执行受控、可回滚的 Skill 配置数据迁移。  

## 目标与边界

本次修复落实“**AI 是助手，人是决策者**”的产品原则。修复不会自动运行任何用户文件、Listing、广告账户、采集任务、关键词任务或 Heartbeat；也不会自动发布内容、修改广告、采购、变价或提交平台。所有高质量 Skill 的输出均被定义为**结构化、可编辑、待人工审核的草案**。

本次不把不同业务问题压缩成一个通用提示词。原有的业务角色、任务边界与输出字段保留；共同补充的仅是事实来源、缺失数据、证据指引、人审和禁止自动执行的治理层。

## 生产审计基线

只读预览确认生产/开发同构的已发布高质量 Skill 范围完整：共 **80** 个，全部命中受治理清单。预览结果显示 80 个当前版本都将发生一次受控更新，模型主路由归并为 3 个既有可用受管路由；不设新的系统默认模型。

| 审计项 | 结果 | 处理方式 |
|---|---:|---|
| 已发布高质量 Skill | 80 | 固定白名单，拒绝缺项或额外项 |
| 将更新的配置 | 80 | 每项先保存不可变快照，再在同一事务中更新 |
| 结构迁移 | 0 | 无 Drizzle/数据库结构变更 |
| 自动模型调用 | 0 | 发布及静态复验不调用模型 |
| 自动业务动作 | 0 | `automaticExecution=prohibited` |

## 修复合同

每个范围内的 Skill Manifest 会写入下列一致合同：

| 层级 | 规则 |
|---|---|
| 输入 | `context` 为必填业务上下文；未提供的事实不得通过猜测补齐。 |
| 事实与证据 | 仅使用输入或已确认的类目/政策资料；主张必须保留输入证据指引，缺失时标记 `needs_verification` 或 `insufficient_data`。 |
| 输出 | JSON 草案模式；保留原任务字段，并附 `_governance` 的草案、人审、缺失输入和限制信息。 |
| 人工决策 | `humanReviewRequired=true`，`recommendationOnly=true`，输出不可视为自动执行授权。 |
| 外部动作 | `automaticExecution=prohibited`；广告、采购、价格、平台提交及发布均需独立人工确认。 |
| 合规 | 未给出明确政策档案时，只能提供“待审核”的合规建议，不能把模型推测写成平台规则。 |

## 路由与执行统一

此前皇帝 Skill 库的 `emperor.run.run` 存在独立的直接模型 HTTP 调用链，可能与业务页面、Agent 和 AI Job 的 `runEmperorSkill` 在模型解析、JSON 模式、凭据引用、审计和人审元数据上不一致。本次将通用运行入口收敛至统一 Runner：

1. 运行时手动选择模型；
2. Skill 专属模型覆盖；
3. Manifest 标准模型策略；
4. 系统默认模型；
5. 在“质量优先”预设中，使用 Skill 的 `qualityModelPolicy`，本次统一为已登记的 `teamo-gpt-6-astra`。

Listing 兼容入口的过期备用模型名也更新为受治理的 Teamorouter Gemini 3.8 Flash、DeepSeek V4 Flash 和 Manus 内置兜底。兜底只影响已发起任务的可用模型选择；不触发自动重试或自动重新解析用户文件。

## UI 与可审计性

皇帝 Skill 库新增“标准”和“质量优先”执行策略选择。对于受治理 Skill，运行结果会明确展示“结构化草案，待人工审核；不会自动发布、修改广告、采购或提交平台”。这使用户可以选择高质量路由，但不会把模型输出误解为已执行的业务结论。

每一次配置更新都会先写入 `emperor_skill_version_snapshots` 的不可变快照，并随即更新运行时版本；回滚工具只会从本次 `governance_migration` 快照恢复，且恢复本身继续递增当前版本以保留审计链。

## 发布和复验计划

1. 打包并 SHA-256 校验 `dist`；在青岛保留版本化备份后原子切换 Web、Worker 与 Scheduler，绝不运行数据库结构迁移。
2. 通过受控数据库脚本执行 80 项配置更新。脚本会在事务内先建快照，若任一项缺失、并发版本不匹配或更新数不为 1，整笔回滚。
3. 只读验证 80 个 Skill 均存在治理标记、`supportsJsonMode=true`、`humanReviewRequired=true`、`automaticExecution=prohibited`，以及 `listing.bullets.generate` 的 GPT-6 Astra 专属路由。
4. 只验证服务活跃、入口哈希、页面资产和数据库配置形状；**不运行模型、不重试用户文件或业务任务**。若以后需要对每个类别执行合成质量评测，应当单独列出样例、模型费用上限和验收标准，再获得明确授权。

## 已执行的生产发布与静态验收

已完成青岛**无结构迁移原子发布**。发布前构建包和三个入口均经 SHA-256 校验；切换前保留版本化 `dist` 备份，切换后 Web、Worker、Scheduler 均为 `active`，本机 HTTP 返回 `200`，三个入口哈希与发布包一致。

随后在运行中 Web 服务继承的受控数据库环境中执行配置迁移。生产预览为 80/80 命中、80 项待更新；实际事务更新 80 项。迁移在逐项更新前写入快照：本次新建 79 个 `governance_migration` 快照，另 1 个 Skill 已有相同不可变版本快照而被唯一约束安全去重；跨所有 80 个 Skill 的历史快照覆盖数为 80。该去重不影响版本更新或回滚能力。

最终只读验证确认：80/80 Skill 均具有治理标记、JSON 草案模式、`humanReviewRequired=true`、`automaticExecution=prohibited` 和 GPT-6 Astra 的质量优先策略；`listing.bullets.generate` 的专属路由为 `teamo-gpt-6-astra`。复验工具明确记录 `noModelCall=true`。本次未调用模型、未读取或重跑用户文件、未创建 AI Job、采集 Job、Provider Run、关键词任务或 Heartbeat。

在首次发布后补充了一个无结构迁移热修：皇帝 Skill 管理后台的创建和编辑入口现在会对这 80 个范围内的 Skill 自动重建同一治理合同。因此，普通编辑无法移除人工复核、证据标记、JSON 草案约束或质量优先模型策略。该热修同样通过原子发布；最终 Web、Worker、Scheduler 均为 `active`，本机 HTTP 为 `200`，入口 SHA-256 与发布包一致，并再次得到 80/80 的只读治理复验。 

## 提示词原样恢复与 Listing 奥美角色层

在用户指出高质量 Skill 的提示词可能与历史版本不同后，生产只读逐项比较确认：73 项仅追加了通用治理文字，6 项因专项治理发生任务提示词替换或清理，另 `listing.bullets.generate` 是此前经用户明确确认的奥美 v3 单独版本。用户选择恢复质量优先的专业提示词，因此执行了受控事务：**79 项恢复到治理前的历史专业提示词**，`listing.bullets.generate` 保留已验收的奥美 v3，所有 21 个 `listing.*` Skill 在原任务提示词之前添加一致、短小的“奥美方法论”角色层。

通用治理长提示词不再注入任何业务 Skill 的运行时 `systemPrompt`；人审、禁止自动执行、质量模型策略、审计元数据和版本快照继续保留在 Manifest、统一 Runner、运行记录及前端提示中。恢复事务为 80 项全部新增可回滚快照。最终只读验证结果为：79 项历史提示词完全匹配、五点生成 v3 保留、21 项 Listing 均含奥美角色层、0 项无效、`noModelCall=true`。随后青岛服务复验 Web、Worker、Scheduler 均为 `active`，本机 HTTP 为 `200`，三个入口 SHA-256 与发布包一致。
