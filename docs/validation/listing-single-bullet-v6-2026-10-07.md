## 一、实施范围

| 层 | 已实施内容 |
|---|---|
| Skill/Prompt | `listing.bullet.step.generate` 是分步骤工作流唯一权威；`listing.bullet.single` 仅用于手动试写。两者复用奥美角色（一次注入）→公开商品发现语义→单条创作简报→结构化 JSON 合同；FABE 仅用于内部判断。`listing.checklist.bullets` 同步升级为非机械的 15 维自检。保持既有模型策略：质量优先时使用受治理质量路由，不擅自更换常规路由。 |
| 服务端 | 两条实际生成路径（工作流Job与再次优化）使用同一确定性 `validateSingleBulletQuality`；严格限制单条输出、标题冒号、长度、字段、目标关键词、短事实引用、数字/材料/认证/保修/比较/兼容性、重复表达和自评完整性；失败有限重试，仍失败则拒绝候选。再次优化不再绕行旧 `listing.bullet.refine`，允许围绕当前草案作实质改写，但拒绝原文返回及与其他已确认卖点高度重复，并核验工作空间。 |
| 自检与前端 | 不强求每条使用数据、认证、场景或完整 FABE。未通过维度必须说明原因、对应摘录（无证据时显式标记）和可编辑建议；可选英文改写仅展示、不自动套用。前端显示真实 Skill、`subtitle + 空格 + fullText`、关键词实际使用；人工编辑、候选切换及优化撤销旧确认与过期自评；内容指纹保护晚到Job/自检；评分按队列保存并绑定草案内容。 |
| Skill 升级 | 脚本默认仅预览；`--apply` 才开启事务，锁定三项 Skill，写入旧版快照并以版本条件更新；状态不符、缺失或竞争更新均失败关闭。按 MySQL JSON 键规范化比较使重复运行预览为零待变更。 |

## 二、本地回归与审查

- 覆盖奥美角色只出现一次、双单条入口同 Prompt、10 项质量自评 Schema 布尔字段、三 Skill 变更幂等。
- 核验事实追溯、格式、长度、数字/材料/比较/兼容性、关键词与重复角度；没有关键词时不强制硬塞。
- 隔离 tRPC 真实优化入口，用模型/数据库 mock 测试唯一 Skill、统一门禁、最多三次校验、原文拒绝、跨工作空间拒绝及失败关闭。**测试没有调用真实模型或 Provider。**
- 检查确认、人工编辑、优化候选与自检异步结果不互相覆盖；开发库更新后只读预览显示三项 Skill 已存在且 `changed: []`。
- 离线核心测试 8 个文件/37 项通过；邻接 Listing/自检/权限测试 9 个文件/279 项通过；改动文件 ESLint 零警告，全站 TypeScript 诊断 0，客户端运行时标识符门禁通过；生产构建与 Bundle 预算通过。Vite 仍提示少量较大的**惰性分包**（已知提示，不等于构建失败）。
- 独立双阶段审查：功能正确性和代码质量/权限/竞态均通过，未发现本轮新增的 HIGH/MEDIUM 问题；本机应用 HTTP 200。构建产物未发现环境文件、私钥、数据库文件、公开代码中的可信凭据字面量/私有路径/内嵌数据库连接。隐私字面量扫描排除了两个仅包裹 WASM 的编码长字符串，避免将其随机字符误报为 AWS 密钥。

## 三、边界与待办

1. 200–280 字符是本产品**内部质量策略**，不是对所有 Amazon 类目的普遍平台限制。确定性门禁能阻止可识别的不合规形式和事实漂移，但不能数学证明英文风格或所有隐含主张正确；仍需人工审核。此轮**未运行真实/合成模型质量测试**。
2. 开发库的三个 Skill 已受控写入并生成升级前快照；**开发库不等于青岛生产库**，青岛生产代码与三个 Skill 均未修改。
3. 获得单独生产授权后，先做只读预检与脚本预览；再事务更新三个生产 Skill、版本化备份并原子发布 Web/Worker/Scheduler；只用静态健康、版本和入口哈希验收。发布过程不发起采集、真实 Listing 生成、Provider 或模型调用，不重跑历史内容。若需要验证文案自然度，应另行取得合成无用户数据模型调用授权及成本边界。
