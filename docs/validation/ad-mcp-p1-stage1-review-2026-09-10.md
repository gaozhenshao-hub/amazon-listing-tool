## 数据安全核对

广告 MCP 仅写入新增的 Profile、广告商品日事实、活动日事实与修订审计表。应用服务回归验证未调用人工上传广告表或 ASIN 日快照表。广告商品为父 ASIN KPI 唯一来源；活动日报仅提供状态和预算，避免活动金额按多个子 ASIN重复累计。

自动应用前必须满足全部授权 Profile 覆盖、全分页读取、无失败窗口、实体身份唯一、字段为有限值及广告商品子 ASIN 精确关联父 ASIN。任一条件不满足时，批次保留待复核且不写入事实。

## 结论

阶段一的**本轮范围功能证据充足**，但因全局 TypeScript 基线不为零，按项目代码审查规范暂不对第二阶段代码质量作“全项目通过”签核。下一步可保存本地版本并请用户确认是否向青岛受控发布；发布后仍须由用户授权一次最小的真实广告 MCP 读取，才能验证完整自然周正式 KPI 的生产数据态。

## 青岛首轮运行前置恢复记录

首次通过已登录生产会话创建广告活动预览时，请求在批次创建前返回 500，未生成同步批次、未成功读取广告 MCP，也未写入广告事实。受管日志定位到运行时 OAuth 服务地址缺失；服务定义仍正确引用受管运行配置文件。随后在用户明确确认后，仅补齐缺失的公开 `OAUTH_SERVER_URL=https://api.manus.im`，创建受限权限配置备份，并重启 Web 服务。恢复脚本仅输出 `OAUTH_RECOVERY_OK`，代表变量存在性、Web 服务 active 与本机 HTTP 健康检查均已通过；未读取或输出其他环境变量、凭据或业务数据。

当前独立青岛部署不具备托管 Heartbeat 外部计划服务，因此不得将广告活动或广告商品任务标记为“已启用自动定时”。首轮必须以同一已发布的受保护预览、完整性门禁、确认与独立事实应用链路做一次手动受治理运行；常规定时计划待部署恢复可用的 Heartbeat 服务后再启用。浏览器自动化会话在恢复后仍有间歇性超时，故截至本记录尚未完成广告活动或广告商品的首轮批次，也没有新增广告业务事实。

## 首轮临时运行器失败边界与修复

为复用同一受保护链路而创建的三次一次性运行器均在 **广告 MCP 调用前** 失败，未创建广告同步批次、未读取广告报告、未写入广告事实。第一次因远程命令转义导致清理钩子参数无效；第二次因 Node ESM 不支持目录导入失败；第三次虽改用 TypeScript 执行器，但青岛当前运行目录只含已发布构建产物，缺少新增源模块，因此不能加载本地开发期模块。以上均属于运维启动方式问题，不构成广告数据质量或完整性门禁的放宽。

后续修复改为在已发布服务路由中增加只限超级管理员的“广告 MCP 首轮受治理验证”入口：固定北京时间前一报告日，串行处理广告活动与广告商品，复用既有预览、全 Profile 覆盖/分页/映射门禁、确认和独立事实应用事务；自动计划保持未创建，搜索词、关键词、投放目标仍不读取。该入口发布后才会再次执行首轮真实读取。
