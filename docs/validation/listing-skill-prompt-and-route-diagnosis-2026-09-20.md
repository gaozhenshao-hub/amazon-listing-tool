# Listing Skill 提示词与模型路由诊断 — 2026-09-20

## 结论

用户截图中的内容对应 **`listing.bullets.generate`（Listing五点描述生成）**，而不是新版逐条卖点精雕 Skill。该 Skill 的当前生产配置存在两个相互独立、但会共同拉低输出稳定性的缺陷。其一，运行时数据库提示词是一个长度为 **5,460** 字符的混合版本，开头保留了旧的中文通用 Listing 角色、A9/A10、消费者心理与“两段式标题结构”等规则，随后才进入五点生成要求。这个标题导向前导段与“五点描述生成”任务并不完全一致，容易造成指令竞争。其二，Skill 的 `modelPolicy` 仍是 **`deepseek-chat`**，而该模型记录当前已停用；因此运行时不会使用它，而会进入备用模型链，导致实际模型与编辑页展示的配置不一致。

> 系统运行时以 `emperor_skills.manifest.implementation.systemPrompt` 为唯一优先提示词来源；`server/prompts.ts` 中的旧代码提示词不会覆盖数据库记录。也就是说，截图中的混合提示词会真实影响生成结果。

## 根因链

1. Listing 生成路由调用受治理 `runEmperorSkill`。
2. `runEmperorSkill` 读取数据库 `emperor_skills.manifest.implementation.systemPrompt`，数据库内容优先于旧代码提示词。
3. 当前五点 Skill 的数据库提示词为混合长度版本，其中含与标题策略相关的旧通用说明；这与单独生成五点的任务边界不一致。
4. 当前 `modelPolicy=deepseek-chat`，但该模型已停用。模型解析器会跳过该条目，进入备用模型链，而不会自动选用当前界面上的默认 DeepSeek V4 Pro。
5. 因为该 Skill 没有历史版本快照，不能声称可以“精确恢复”用户此前任一版本的完整原文。

## 推荐受控修复

修复应一次完成，但应先由用户确认**默认模型路由**。推荐方案是将当前混合提示词先写入不可变“修复前”快照，再创建版本 3 的单一任务提示词：保留已验证的 FABE、每条 200–280 字符、五条排序、JSON 输出和真实事实约束，移除与标题生成冲突的旧通用前导段。随后将五点 Skill 的 `modelPolicy` 从已停用的 `deepseek-chat` 更新为用户确认的活动模型。

| 选择 | 路由 | 适用性 | 成本影响 |
|---|---|---|---|
| **标准稳定（建议）** | `teamo-deepseek-v4-pro` | 常规 Listing 五点生成；与当前默认模型一致，避免停用模型降级 | 按 Teamorouter 实际账单；仅在用户主动生成时产生费用 |
| **高质量优先** | `teamo-gpt-6-astra` | 高价值、竞争激烈或需要更强推理的 Listing | 按 Teamorouter 实际账单，通常高于标准路由 |

无论选择哪一项，修复发布后先只验证：提示词哈希、模型路由解析、服务健康和版本快照；**不会自动重试或覆盖既有 Listing**。如果需要使用一份不含用户产品数据的合成样例做质量验收，则须额外获得一次模型调用和费用授权。
