# SellerSprite 竞品批量分析失败诊断与修复

**日期：** 2026-09-23  
**范围：** 青岛独立站 `www.kuahaixing.com` 与 Manus 托管站 `amzlisting-a79tkwus.manus.space` 的“竞品分析 → 卖家精灵数据导入”流程。  
**安全边界：** 本次复验未调用模型、未重试截图中的 18 条记录、未创建采集任务、未改变 Provider 资格状态或密钥。

## 用户可见症状

卖家精灵表格批量分析结束后仅显示“分析完成：0 成功，18 失败”，右侧没有结果，页面也没有给出每个 ASIN 的失败原因。该提示不能证明 Excel 解析失败；其只代表 18 条逐项分析均在写入结果前失败。

## 证据与结论

历史批量接口将每一条异常压缩为 `asin + error.message`，前端只汇总成功/失败计数，且历史记录没有可用于逐项还原的安全失败分类。因此，**不能把已有 18 条失败归因到某一个 ASIN 或单一 Provider 响应**，也不能在缺乏用户授权的情况下重跑它们。

针对当前路由做了只读 `GET /v1/models` 核验。托管站与青岛站的受控 Teamorouter 凭据均已配置，模型目录均返回 44 个模型，竞品 Skill 配置的 `claude-opus-5` 与 `gpt-6-astra` 均在目录中。该核验不产生模型生成费用。

同时发现双站存在历史端点漂移：青岛记录使用官方 `.cn` 入口，而托管站仍有持久化 `.com` 基址。旧 `.com` 入口曾依赖已退役的 SOCKS 出口，属于会使批量分析在模型调用前失败的兼容性风险。修复后，运行时和模型管理健康检查都会把遗留 Teamorouter OpenAI 兼容入口规范为官方 `.cn`；不修改密钥、不修改模型策略。

## 已实施修复

| 层级 | 修复 | 防重复与安全效果 |
|---|---|---|
| 模型执行 | 规范遗留 Teamorouter `.com` 基址为 `.cn` | 不再依赖退役 SOCKS；不触碰密钥 |
| 批处理接口 | 将异常转换为受控的分类、可重试性和中文提示 | 不向客户端泄露 Provider 载荷、令牌或内部栈 |
| 批处理界面 | 显示逐个 ASIN 的失败原因及“可人工重试/需先修复配置” | 用户可定位问题；不会把成功项再次提交 |
| 选择状态 | 成功行自动取消勾选，失败行保留勾选 | 重试必须由用户明确点击；系统不自动重跑 |
| 回归与构建 | 新增失败分类、端点规范化和前端反馈契约测试 | 防止错误重新退化为仅有“18 失败” |

## 用户操作说明

重新导入卖家精灵数据并点击批量分析后，若仍有失败，页面会显示每个失败 ASIN 的说明。成功项会自动取消勾选；失败项会继续保持勾选，但不会自动重试。请先依据页面说明处理原因，再由人工决定是否再次点击分析。
