# 已入库负责人名称映射候选审计（2026-09-13）

## 范围与安全边界

本审计仅对青岛生产中已入库、有效的领星ASIN日快照负责人原始名称执行聚合检查。审计通过受管环境临时单元运行，脚本在运行前完成SHA-256校验，执行后自动删除。它未调用领星MCP、未读取原始业务指标、未返回人员姓名或产品明细，亦未新增、修改或删除负责人名称映射与人工负责人规则。

## 审计结果

| 项目 | 聚合结果 | 结论 |
| --- | ---: | --- |
| 已入库外部负责人名称 | 9 | 可作为查询时动态解析的名称范围 |
| 已确认名称映射 | 5 | 既有历史数据与后续读取均可立即复用 |
| 活跃人员精确名称候选 | 0 | 不存在可无歧义自动新增的精确同名映射 |
| 既有映射冲突 | 0 | 无需清理冲突记录 |
| 同名活跃人员冲突 | 0 | 无同名候选风险 |
| 无精确活跃人员匹配 | 4 | 不能按名称相似度推断归属 |
| 多条人工规则一致证据候选 | 0 | 不能以既有人工父ASIN规则自动升级为全局名称映射 |
| 人工规则证据不足 | 4 | 每项须人工指定目标人员后才能写入 |
| 人工规则混合负责人 | 0 | 未发现相互矛盾的人工规则证据 |

> 结论：当前5项已确认映射已即时作用于历史查询；其余4项缺少精确或足够独立证据。为避免错误地把一个外部负责人全局映射到不对应的系统人员，系统保持失败关闭，待用户提供明确的“外部名称 → 系统人员”对应关系后再批量写入。

## 用户确认后的受治理写入与回查

用户已明确确认，将4项待确认外部负责人名称均映射至同一指定的活跃系统人员。写入脚本在执行前核验目标人员在工作空间内唯一且活跃，并锁定检查四个外部名称不存在冲突映射；若任一前置条件不满足，整个事务会失败关闭。生产受管单元返回`requested=4`、`inserted=4`、`unchanged=0`与`sourceType=lingxing`，表明四项确认映射均已新增。

随后仅运行聚合回查：4项指定名称均处于确认状态，目标无不一致；9个已入库外部负责人名称均可由确认映射解析，未解析名称为0。未发起领星MCP读取，未改写任何日快照、原始负责人标识、人工父ASIN×店铺×站点规则或其他业务事实。
