# Listing 单条卖点 v7：空白与示例事实防护

**日期：** 2026-10-07
**状态：** 本地与青岛生产均已完成两项 v7 Skill 同步及应用原子发布；未触发模型或历史重跑
**依据：** 上轮历史影子评估在 65 条候选中发现 11 条把原始属性表的空白/示例当事实；该数字不是本轮 v7 通过率。

## 根因与修复

| 层 | 已实现的安全边界 |
|---|---|
| 前端 | 卖点核心中的空白、待填、例如/e.g.、带例子的括号字段以字段路径提示；确认前须人工修正。旧核心可重新编辑，既有草案和所有优化候选保留但失效；**仅点击编辑并保存也不能恢复旧草案的确认资格**，旧异步 Job 不能覆盖改后的核心。无证据核心不能启动生成；模型草案仍由人选择、编辑、确认。 |
| 输入编译 | G1 核心、G1 整套五点（含旧批量双阶段）与逐条 Job 均清理项目参数和属性分析树；对照**同一份最新有效原始上传**剔除即使已被 AI 分析去掉“示例”标签的示例取值，包括字符串与数字型裸值。4KB数据库预览不足时仅从可信存储读取完整原文并核验指纹，否则失败关闭。逐条 Skill 只接收简化产品身份、人工选中核心和已确认卖点作差异参考；原始竞品/属性分析不作为该条的事实入模。原始上传和现有 Listing 均不被修改。 |
| 后端门禁 | 生成和再次优化对仅示例/空白核心失败关闭；原始上传的示例值在分析或当前核心出现先拒绝，不消费模型。G1核心模型自行输出原表示例时整批失败关闭；**五点第一稿及格式重试后的最终稿都再核验示例值**，不将其作为待人审候选。数字/规格/材料从选中核心与短证据双重追溯；示例数字、空规格营销话术不能凭自评过关。皇帝库手动试写对显式占位/示例预检；因试写不绑定项目，不声称能交叉查验原表。 |
| 项目隔离 | Listing编辑、读取、版本、计划、自检及新旧生成Job均以当前工作空间读取项目，Job执行期再以审批时的workspaceId校验；同秒重复上传及同秒AI任务分别以`createdAt DESC,id DESC`稳定排序。工作空间仅用于权限判定和审计，不把签名URL或上传原文送给客户端。 |
| Skill治理 | `listing.bullet.step.generate`（工作流权威）与 `listing.bullet.single`（仅手动试写）统一更新 v7 事实源/模板示例合同；奥美角色只注入一次，FABE 不机械化，质量优先路由保留。v7 脚本只更新这两项，默认 preview；应用需事务/旧版快照/乐观版本并复验幂等。旧 v6 脚本已封存不可误执行；15维自检 Skill 不在本轮更新范围。 |

**限制：** 字符格式、短证据追溯和模板识别不能证明一条文案的商业主张或自然美式英语必然正确；上传原文本身错误、无证明材料或人工误确认仍须运营人员核实与编辑。前端的人审确认态尚未建立可由服务端独立验证的持久“核心版本—操作者—证据”绑定；必须在后续设计该产品化能力，不能把内存中的状态说成已核实事实。过滤不会自动补全数值。历史影子 65 条草案不会因本轮代码改动自动重做或写回。
