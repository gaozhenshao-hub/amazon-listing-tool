# GPT‑6 Astra 选择与运行路由诊断

**日期：** 2026-09-20  
**范围：** 皇帝 Skill 库的模型配置与运行界面。  
**边界：** 生产诊断为只读；发布仅修改 UI，不修改任一 Skill 的标准默认模型，不调用模型。

## 根因

用户截图中的“Listing 产品描述生成”在模型配置页显示 Claude Opus 5，是因为该页面展示的是此 Skill 的**标准默认模型覆盖**。生产只读数据确认该 Skill 的标准路由为 `teamo-claude-opus-5`，而其 `qualityModelPolicy` 已正确配置为 `teamo-gpt-6-astra`。GPT‑6 Astra 在生产模型目录中已注册且激活。

因此，问题不是 GPT‑6 Astra 未接入或“质量优先”失效，而是界面把“标准默认模型”和“质量优先模型”混在一个不易检索的长下拉列表中。用户无法直观看到质量优先已经走 GPT‑6，也缺少将标准路由直接改为 GPT‑6 的明显入口。

## 修复

模型配置页现将 GPT‑6 Astra 固定置顶，并新增 **“设为 GPT‑6 Astra”** 快捷按钮。页面明确显示“标准执行”和“质量优先执行”的实际路由；标准模型选择中也标记了“GPT‑6 Astra（质量优先推荐）”。运行面板改为传递受控模型 **slug** 而不是 model ID，以便审计记录与模型目录使用同一稳定标识。

> 使用方法：如果仅需要本次输出高质量，在运行区选择“质量优先”即可，无需修改标准默认模型。如果希望该 Skill 后续每次标准运行也使用 GPT‑6 Astra，在模型配置页点击“设为 GPT‑6 Astra”，再点击“保存更改”。后者会提高该 Skill 的常规模型成本。

## 验证

定向 Skill 库 UI、治理路由和统一 Run Router 回归通过；ESLint、生产构建和 Bundle 预算通过，修改文件无新增 TypeScript 诊断。青岛无迁移原子发布后，Web、Worker、Scheduler 均为 `active`，本机 HTTP 为 `200`，发布前后入口哈希一致，生产静态资源包含新的 GPT‑6 控件字符串。未执行模型调用、未创建或重试任何业务任务。
