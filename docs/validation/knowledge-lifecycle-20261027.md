# 知识库调整与回收站

本次修改把知识库图片和视频的单次 AI 指令改为可核对的多轮草稿；明确确认才写入标签，确认改进前展示判断方法、修改内容和团队/个人范围。确认的纠正案例会被后续图片、套图、视频打标读取，不自动改写正式 Skill 或 Agent 定义。

图片操作仅在展开预览下方出现。A+ 组合模块整体处理，导航轮播各自处理；品牌故事不参与打标。删除、恢复及永久删除均由服务端验证管理员和工作空间，回收站位于采集入口下方。永久删除仅清理未被其他记录引用的对象，旧采集快照仍引用的对象保留；没有扩大删除采集缓存的范围。

重新采集使用原始 ASIN，确认采集完成后更新当前套图；重复点击复用进行中的任务。删除与重新采集互斥，回收站中的套图不能被采集任务覆盖。

验证：

- 35 个相关测试文件、158 项测试通过，覆盖多轮上下文、确认/放弃、改进二次确认、并发修改冲突、权限、组合模块、轮播、原有图文/视频展示和打标。
- TypeScript 检查、客户端运行时标识检查、构建、包体积、发布功能、业务 Skill 边界、领域边界检查通过。
- 修改文件 ESLint 无错误；新增操作组件的 effect 依赖警告已修正。
- MySQL 8.4 临时表验证通过：管理员/租户隔离，组合模块回收/恢复，父集恢复不恢复此前单独回收的子项，确认改进幂等，视频/模块永久删除后的布局，重新采集目标和互斥。整个测试回滚，无业务记录提交、无文件删除、无模型调用。
- 全局业务任务绑定审计仍报告原有 automaticTagging、standaloneImages 的 4 项 agentRunId/agentNodeId 缺项；本次未改动这两个任务的绑定结构。

部署需要先执行专用增量迁移 `0247_knowledge_asset_lifecycle.sql`。新表及回收标识均为增量字段，不改变已有图片、视频、Skill 或 Agent 数据。发布脚本比对前后业务数据摘要，应用失败时恢复上一应用镜像。
