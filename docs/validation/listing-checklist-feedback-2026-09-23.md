# Listing 自检未通过原因与修改建议

**日期：** 2026-09-23  
**范围：** Listing 五点、标题、产品描述、搜索词和 Q&A 的自检结果。  
**用户需求：** 对每一个未通过的自检维度，明确显示未通过原因和可执行的修改建议。  
**执行边界：** 未重跑任何用户 Listing、未调用模型、未自动改写或确认任何文案。

## 实现结果

自检结果现在不是只有“通过/未通过”和笼统备注。对于每一个未通过维度，系统会要求 GPT‑6 Astra 的受治理自检 Skill 返回并展示以下内容：

| 字段 | 前端展示 | 约束 |
|---|---|---|
| `reason` | **未通过原因** | 指向缺少、不一致或不符合规则的具体点，禁止空泛结论 |
| `suggestion` | **修改建议** | 给出一项可由人工编辑的具体改法；只能基于现有产品事实，不得编造数字、认证、质保或其他声明 |
| `evidenceQuote` | **对应内容** | 可选的原文短引或可观察事实，帮助定位要修改的位置 |
| `notes` | **通过依据** | 通过项的简要依据；未通过项不再只显示不透明的技术备注 |

一旦新一次自检存在未通过项，面板会自动展开，避免原因和建议被折叠的评分摘要隐藏。系统仍然只提供建议，**不自动改写卖点或自动确认内容**。

## 质量与失败关闭控制

五类自检均已要求每个维度返回 `pass`、`notes`、`reason`、`suggestion` 和 `evidenceQuote`。任何一个维度缺失字段，或未通过项缺少非空原因/建议，整份结果均被视为不完整，不会写入或渲染为分数，并提示用户重新自检。这样可以避免再次将模型格式问题误呈现为内容质量不合格。

五类自检继续使用受治理的 **GPT‑6 Astra** 质量优先路由，保持 JSON 草案、人审和禁止自动执行的治理设置。

## 使用方式

对已有内容点击 **Check List 自检**。若存在未通过项，系统会自动展开评分面板，并逐项显示“未通过原因”“对应内容（如有）”和“修改建议”。用户可基于建议选择编辑、重新生成或保留原文；建议本身不会修改数据。
