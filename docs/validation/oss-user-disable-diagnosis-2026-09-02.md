## 官方含义与最小恢复路径

阿里云官方文档将`0003-00000801`解释为“账号处于被禁用状态”，原因包括账号欠费、安全原因被禁用或未开通OSS服务。[1] 官方403错误说明同样将`UserDisable`归因为账户禁用或未开通OSS，而与常规对象权限不足的`AccessDenied`区分。[2]

因此，最小恢复顺序为：先在阿里云控制台核验账号状态、费用与成本、OSS服务开通状态，以及RAM用户/AccessKey是否仍处于启用状态；若账号或AccessKey被安全限制，按控制台提示恢复或使用新的最小权限RAM AccessKey。只有在这些前提恢复后，才应进行一次小体积、受控的Artifact写入验证；不得通过放宽Bucket访问控制、公开Bucket或停用审计来绕过问题。

| 核验项目 | 所需权限 | 可接受结论 |
| --- | --- | --- |
| 账号与费用状态 | 账号所有者/财务只读 | 账号正常、无导致服务暂停的欠费 |
| OSS服务状态 | OSS控制台只读 | 服务已开通，目标Bucket正常 |
| RAM用户与AccessKey状态 | RAM只读 | 现用凭据所属身份和AccessKey均为启用状态 |
| Bucket写入最小权限 | RAM/OSS策略只读 | 仅允许目标Bucket指定前缀的`PutObject`，不扩大公开访问 |
| 恢复验证 | 用户明确授权 | 仅写入受控测试Artifact，成功后清理或按保留策略归档 |
