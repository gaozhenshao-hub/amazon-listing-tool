# A+ 与品牌故事采集能力资格验证

**日期：** 2026-09-28  
**范围：** 青岛独立站主 Amazon 图片采集 Provider（`apify-amazon-primary`）  
**授权边界：** 用户明确授权一次受控扩展资格任务，最高 **0.10 USD**；验证成功才恢复图片知识库的完整四项采集请求。

## 根因

先前主 Provider 的实样资格仅验证了：

- `catalog_basic`
- `image_gallery`

图片知识库完整导入同时请求 `aplus` 与 `brand_story`。统一门禁会拒绝未获资格的能力，因此截图中的阻断是**正确的失败关闭行为**，而不是凭证、预算或浏览器错误。此前临时将默认导入缩窄为主/副图，虽可创建任务，但不满足完整图片研究需求。

## 受控扩展资格任务

实现了独立的富内容资格路径，具备以下安全边界：

| 控制项 | 行为 |
|---|---|
| 前置条件 | Provider 必须已激活且已有基础目录/图库资格 |
| 一次性限制 | 使用独立幂等键；若失败关闭，不自动重试 |
| 能力门槛 | 同一返回中必须实际观测到基础目录、图库、A+、品牌故事四项 |
| 失败行为 | 保持既有 `catalog_basic`/`image_gallery` 可用，不升级 A+/品牌故事 |
| 数据隔离 | 样本 ASIN、URL、原始载荷和图片只在进程内使用；不写业务 Snapshot、客户端或本文档 |
| 审计 | 只保留脱敏 Qualification Job/Run、能力集合、费用与失败类别 |

验证样本从既有图片知识库的**已存在元数据**中只读选择，选择过程不输出样本 ASIN；运行前即删除临时样本文件。

## 完整导入恢复

图片知识库的 ASIN、链接和批量导入已恢复请求完整四项能力：基础商品信息、主/副图、可获取的 A+ 与品牌故事。每个业务采集仍将：

1. 受单次、日、月预算约束；
2. 生成独立 Acquisition Job/Run 与候选 Snapshot；
3. 等待人工审核确认后才进入图片知识库或 AI 分析；
4. 在 Provider 失败时失败关闭，绝不回退旧 HTML 爬虫。

发布后已验证 Web、Worker、Scheduler 均为 `active`，本机 HTTP 为 200，完整能力标记存在，资格样本临时文件和执行器均已清除。
