# 图片知识库首次导入能力门禁修复

**日期：** 2026-09-28  
**范围：** 图片知识库的单个 ASIN、链接与批量 ASIN 导入。  
**边界：** 本次仅修复任务创建前的能力请求集合和页面说明；没有创建业务采集任务、Provider Run、AI Job、关键词任务或 Heartbeat。

## 用户症状

图片知识库的“创建受控采集任务”被拒绝，页面显示 Provider 尚未完成 `aplus`、`brand_story` 的资格验证。该提示来自能力门禁，不是系统错误。

## 证据与根因

| 核对项 | 结果 |
| --- | --- |
| 青岛主 Provider Profile | `active` |
| 已资格能力 | `catalog_basic`、`image_gallery` |
| 未资格能力 | `aplus`、`brand_story` |
| 首次导入的旧请求集合 | 基础信息、主/副图库、A+、品牌故事四项能力 |

因此，首次图片导入将尚未资格验证的可选能力作为硬性前置条件，与 Provider 的有效能力集冲突，导致任务在 Provider 外呼前被正确失败关闭。

## 修复

首次单 ASIN、链接和批量导入现在默认只请求：

```text
catalog_basic + image_gallery
```

A+ 与品牌故事不被自动开启，也没有被标记为已验证。它们只会在用户明确选择相应图位的刷新流程中被单独请求；若仍未通过资格验证，系统继续返回可读的预条件错误且不创建 Job/Run。导入页说明同步改为准确描述当前能力边界。

## 验证与发布

- 定向 Vitest：2 个文件、4 项测试通过；覆盖默认能力集、显式 A+/品牌故事刷新能力映射和未启用 Provider 的失败关闭路径。
- ESLint、客户端未定义标识符门禁、生产构建和 Bundle 预算均通过。
- 定向 TypeScript 新增诊断为 0；全局仍有 146 项既有历史诊断，未宣称全绿。
- 青岛无迁移原子发布完成：Web、Worker、Scheduler 均为 `active`，本机 HTTP 健康检查通过，三项入口 SHA-256 与构建包一致。
- 公共图片库分块返回 HTTP 200，并已包含更新后的资格提示。

## 用户后续操作

刷新图片知识库页面后，重新输入 ASIN 并点击“创建受控采集任务”。该操作将仅创建待人工审核的基础信息和主/副图采集任务；是否发生 Provider 费用仍由运行时预算、缓存及 Provider 计费规则决定。A+/品牌故事继续等待单独资格验证，不能作为本次初始导入的隐式请求。
