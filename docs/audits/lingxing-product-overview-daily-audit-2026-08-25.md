# 领星产品总览日数据与父ASIN周度审计

**审计日期：** 2026-08-25  
**范围：** 只读审计领星MCP能力、现有日快照、产品总览聚合路径与截图中的指标归零问题。不写入或覆盖业务数据。

## 结论

领星官方MCP的 `query_product_performance_asin_lists` 工具支持 `date_view_type=day`、`summary_field=asin`、店铺、国家及日期范围筛选，因此可作为ASIN日数据的受治理读取来源。实际调用前仍需用户确认店铺、站点和日期范围；当前不执行该MCP读取。

现有产品总览的近期领星数据来自 `ops_asin_daily_snapshots`，共5,005条，覆盖2026-08-03至2026-08-16、337个父ASIN和405个子ASIN。数据由两批历史导入提供：批次600001（2026-08-10至08-16，2,513行）和批次570001（2026-08-03至08-09，2,492行）。

## 截图问题的证据

截图中的父ASIN为 `B0H1Q46PVH`。2026-08-10自然周的日快照包含4个子ASIN；按原子字段求和后，销量为135、Session为767、广告点击为337、广告曝光为19,388、广告订单为54、广告花费为748.68美元。销售、Session和广告花费已经与截图相符，但总CVR、广告CVR、广告订单、点击、曝光、CTR和CPC在前端适配层被写死为0，因此显示错误。

> 根因是前端 `adaptDailyParentOverview` 未映射日快照已存在的指标，不是源数据为0，也不是父ASIN多变体本身无法汇总。

## 修复后的指标规则

| 类别 | 父ASIN周度规则 | 缺失处理 |
| --- | --- | --- |
| 销量、订单、销售额、订单利润、Session、广告花费、广告销售额、广告订单、自然订单、广告点击、广告曝光、退货量 | 按父ASIN、店铺、站点和自然周对各子ASIN逐日原子值求和 | 原子源字段为0时保留真实0 |
| 总CVR | 周订单数 / 周Session | Session为0时不提供 |
| 广告CVR | 周广告订单 / 周广告点击 | 广告点击为0时不提供 |
| CTR | 周广告点击 / 周广告曝光 | 广告曝光为0时不提供 |
| CPC | 周广告花费 / 周广告点击 | 广告点击为0时不提供 |
| ACOS | 周广告花费 / 周广告销售额 | 广告销售额为0时不提供 |
| 利润率、退货率 | 周订单利润 / 周销售额；周退货量 / 周销量 | 分母为0时不提供 |
| 自然CVR、评分、评论 | 日快照没有自然点击、评分和评论原子字段 | 页面显示“数据未提供”，不得伪造成0%或0 |
| 库存 | 每个子ASIN只取该自然周最后一个报告日快照，再求和 | 避免每日库存快照重复累计 |

## 数据源优先级

同一父ASIN、店铺、站点和自然周，领星日快照优先于历史周度Excel；无日快照的历史周保留周度导入记录。合并按周替换而非相加，防止双重累计。历史原始导入保持不修改。

## 领星MCP美国站只读预览

经用户确认，预览范围为美国站全部授权店铺和2026-08-10至2026-08-16。店铺目录中共有9个美国站SID：7392、12507、7395、10261、10927、12262、13627、14088、10930。按照QPS=1逐店读取后，所有调用均返回成功结构；7个店铺首行返回有效ASIN，SID 13627与14088首行返回占位值 `asin="-"`，后续正式同步必须过滤该占位行并继续分页，不能作为产品记录写入。

单日样本（2026-08-10）已确认返回的 `rdate` 与请求日一致。MCP同时提供销售额（`amount`）、销量（`volume`）、订单（`order_items`）、毛利（`gross_profit`）、总Session（`sessions_total`）、广告订单（`ad_order_quantity`）、广告销售额（`ad_sales_amount`）、广告花费（`spend`）、点击（`clicks`）、曝光（`impressions`）、自然点击（`nature_click`）、自然订单（`nature_order_items`）、评分（`avg_star`）、评论（`reviews_count`）、退货相关字段、库存与父ASIN数组。因此，MCP字段覆盖优于现有日快照；但本轮仅为只读预览，未创建导入批次、未写入日快照或产品总览。

> 正式写入必须先呈现分页完整的行数、无效/占位行过滤结果、MCP字段到日快照字段的归一化映射以及与已有日快照的逐日差异；仅在人工确认后追加新的可审计批次。

已登录工作空间的同步页面已真实显示批次#3（3,759行、63条占位ASIN过滤、无截断及受控原始响应归档）和已启用的两个计划。每日任务UID为`Gu5NVZ7EUCj3XERAfVUHdQ`，北京时间17:00读取前一天；周汇总任务UID为`4rEeuGVc8r9WpCNJuD7bkV`，北京时间周一17:10执行。每日计划的`auto_apply=1`，每周计划的`auto_apply=0`；两项在本审计时均为`idle`，未提前触发首轮同步。

每日自动应用仅在草稿满足下表治理条件时才调用既有确认与追加日快照路径。任何一项失败都会将计划标记为失败并保留草稿供人工处理，库存、广告、Listing、人工货期、缓冲、MOQ、成本、财务利润和广告配置均不进入该自动写入路径。

| 自动应用校验 | 拒绝后果 |
| --- | --- |
| 单日报告期、授权店铺数及店铺×日期窗口完整 | 保留草稿并转人工 |
| 无分页截断、无5000行上限截断 | 保留草稿并转人工 |
| 有效且去重的店铺/站点/ASIN/报告日身份键 | 保留草稿并转人工 |
| 非占位ASIN、父ASIN与报告日齐全；指标为非负有限数 | 保留草稿并转人工 |
| 同店同ASIN与前一日相比不存在阈值外异常跃升 | 保留草稿并转人工 |

每日摘要中的授权店铺数与店铺×日期窗口数来自每个实际完整返回的分页窗口；任何页数上限、5000行上限或未遍历窗口都不会被计作已覆盖。这样，自动应用不能因预期范围被直接回填而绕过覆盖校验。

每周父ASIN汇总依然是仅草稿。周批次会结构化记录已确认日快照的预期日期、实际日期、缺失日期与异常类型：`missing_daily_coverage`、`empty_week`、`all_zero_metrics`和`upstream_lineage_unverified`。出现任一异常时行级校验信息提示“仅供人工审阅”，不改写历史周表或人工财务。
