# 阿里云低成本单机部署方案

本文将原“生产稳妥版”的多服务拆分方案调整为**低成本启动版**。目标是在不改变现有业务页面、图片工作流或AI编排的前提下，用一台青岛ECS承载应用、MySQL、AI Worker和Scheduler；对象文件仍使用青岛私有OSS。RDS将在业务稳定、数据量或并发上升后再拆分。

## 推荐采购方案

| 资源 | 低成本启动版 | 原生产稳妥版 | 说明 |
|---|---:|---:|---|
| ECS | 4核8GB、100GB ESSD PL1、Ubuntu 24.04 | 8核16GB、200GB ESSD | 单机运行应用、MySQL、Worker、Scheduler。CPU/内存不足时可原地升配。 |
| 数据库 | ECS内Docker MySQL 8（不开放公网） | RDS MySQL 8高可用版 | 以每日逻辑备份和云盘快照换取较低初始成本。 |
| OSS | 杭州私有Bucket，按量付费 | 同 | 保存图片、导出文件和未来附件；应用使用签名URL授权访问。 |
| 带宽 | 3–5Mbps BGP起步 | 5Mbps以上 | 图片和文件应优先走OSS签名下载，避免应用服务器承载文件流量。 |

> 此方案适合当前以内部团队使用、低并发为主的第一阶段。单机故障会同时影响应用和数据库，因此不适合已经要求高可用或有大量并发写入的生产阶段。

## 成本控制原则

青岛属于阿里云中国内地地域。ECS支持按需升降计算、存储和网络资源，因此低成本启动版应选择可升配的通用实例，不要购买无法扩容的极低配突发型实例。[1]

### 计费方式与活动价情景（2026-08-23核验）

阿里云将**包年包月**定位为固定、长期运行服务的预付费方式，将**按量付费**定位为临时扩展、测试或突发负载的后付费方式；同一实例可在控制台支持时转换计费方式，但转换资格和价格均随资源与订单状态变化。[5] 因此，当前已长期运行 Web、MySQL、Worker 与 Scheduler 的青岛4核8GB单机，应以包年包月报价与续费页为主决策依据；按量付费只作为短期扩容、迁移演练或可随时释放的测试资源口径。

| 情景 | 官方可核验样例/计算口径 | 适用性 | 不应误读的边界 |
|---|---:|---|---|
| 当前4核8GB单机按公开按量基线 | 3Mbps约508.90元/月（年化6106.80元）；5Mbps约557.50元/月（年化6690.00元） | 用于与当前规格接近的保守预算上限 | 为此前公开标价基线，非青岛实际账单或订单报价 |
| 当前4核8GB单机包年包月 | 以订单页实例、云盘与带宽的订阅总价除以12计算等效月费 | 推荐用于长期24×7服务 | 官方仅说明订阅通常有较低单价；本轮未取得与当前实例族、青岛可用区完全一致的公开定额，不能用入门活动价替代 |
| 官方入门活动样例 | 经济型e实例2核2GB、3Mbps、40GB ESSD Entry：99元/年；页面列日常价1507.56元/年，样例优惠约94.00% | 个人站点、开发测试、低负载项目 | **不适用于本项目当前4核8GB + 本机MySQL + Worker负载**；活动配置、资格、库存和续费规则以页面实时规则为准 |
| 官方轻量活动样例 | 轻量应用服务器2核2GB、200Mbps峰值：68元/年 | 临时验证、小型应用或新用户活动 | 轻量套餐与当前ECS、私有OSS、Nginx/systemd和本机数据库运维基线不同，不作为现网替换报价 |

> 活动价格是**特定配置、资格、库存与规则**下的营销价，不是4核8GB生产规格的比例折扣。对于已经承载数据库和后台任务的青岛ECS，不应为了追逐入门活动价直接降配或切换产品；应在控制台对当前实例分别获取按量、包年包月、续费和升降配报价后，再进行人工决策。

建议每月在费用中心记录四个数：当前ECS实例/云盘/带宽账单、包年包月续费报价、同规格按量报价，以及OSS/快照/模型网关可变费用。只有当订阅节省额覆盖合同期灵活性损失，并且业务至少连续稳定运行一个购买周期时，才应人工转换；不由应用或脚本自动更改任何计费方式。

OSS中国内地按量计费下，本地冗余标准存储为 **0.12元/GB/月**；同地域ECS通过内网Endpoint访问OSS的内网流出免费。初期无需购买OSS资源包，待容量和外网下载量稳定后再评估包年包月资源包。[3]

为控制OSS成本，应将当前频繁访问的图片保留在标准存储；对历史导出文件和长期不访问资产配置生命周期规则，再转低频或归档。低频和归档读取会产生额外取回成本，因此不应把图片工作流当前资产直接归档。[3]

## 安全与备份底线

MySQL只监听Docker内部网络或`127.0.0.1`，不开放3306公网端口。安全组仅开放80/443，并将22限制到管理员固定IP。每日执行加密逻辑备份到私有OSS；同步启用ECS云盘快照。该机制不能替代RDS高可用，但可为低成本启动阶段提供可恢复性。

升级触发条件是：连续一周内存使用率长期超过70%、AI Worker高峰明显排队、数据库备份窗口过长、或开始面向外部多团队使用。届时先把MySQL迁入RDS，再把Worker拆至第二台ECS。

## 采购后执行顺序

1. 购买杭州ECS与私有OSS Bucket，配置VPC、安全组、RAM最小权限子账号和测试域名。
2. 通过`deploy/aliyun/preflight.sh`检查Docker、Compose、`.env`、端口；应用已运行后加`--check-health`。
3. 在ECS启动MySQL和应用三进程，再恢复经验证的数据备份。
4. 用测试域名验证邮箱登录、OSS签名下载、外部模型网关、Worker/Scheduler及图片工作流。
5. 保留Manus入口作为回滚通道，完成灰度后才切换正式域名。
