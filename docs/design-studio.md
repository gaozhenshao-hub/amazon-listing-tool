# 美工板块 / 生图

独立入口 `/design/images`，默认向管理员和美工开放，遵循角色目录的只读、编辑、删除权限。对话、生成记录、原图和参考图按工作空间及本人隔离，不复用或更改 Listing 图片工作流。

## 使用

- 新建对话，先与 GEM 3.8 Flash 讨论需求；可上传、拖入或粘贴最多 16 张参考图。聊天只理解图片、追问和整理方案，不直接生图。
- 方案准备好后可查看完整提示词，继续讨论或点击“确认并生成”，由 TT Image 2.5 生图。只有最新一轮的方案可确认；继续聊天会使旧方案失效。修改画面参数后需更新方案。
- 单张参考图不超过 10MB，合计不超过 30MB；接受 PNG、JPEG、WebP、GIF，并在服务端解码校验。
- 每次生成 1 张。设置版本、比例、分辨率、画质和背景；自动比例与自动分辨率联动。
- 点击图片放大、下载原图；“继续修改”将结果作为参考图，“重新编辑”恢复提示词、参数与参考图，“重新准备方案”重新进入沟通，均需再次确认才会生图。
- 历史自动保存，可以重命名、删除对话或单条记录。生成中的记录不可删除。

## 部署

1. 备份数据库，按顺序执行 `drizzle/0232_design_studio.sql`、`drizzle/0233_design_conversation_title.sql` 和 `drizzle/0234_design_chat.sql` 并记录 `app_schema_migrations`；使用 UTF-8 连接。0234 新增持久化聊天队列、方案及确认关联，不修改已有生成记录。
2. Web 与 AI worker 需共享私有持久化目录。可指定 `DESIGN_STUDIO_STORAGE_ROOT`，默认使用 `LISTING_SUPPLEMENT_LOCAL_ROOT/design-studio`。目录不可公开静态映射。
3. 模型注册表中启用 `tt-image-2.5-token` 和 `gem-3.8-flash`，配置 `https://api.lk888.ai/v1` 及各自服务端凭据。GEM 使用 `/v1beta/models/gem-3.8-flash:generateContent` 原生接口，支持参考图和结构化方案。Web 不向浏览器返回密钥。聊天与生图分别计费。
4. 发布 Web、AI worker；生成轮询在 AI worker 中运行。开发环境也需启动 worker。
5. 回滚应用镜像不会丢失新表和图片。备份应覆盖数据库以及上述图片目录。

## 执行与恢复

提交请求有本人范围的幂等键；同一对话同时一个生成任务，每人最多两个。任务领取使用数据库行锁和租约，生成前保存提交状态，获取服务任务号后立即持久化。

聊天每人同时一个任务，保留最近 40 轮成功对话上下文；参考图为当前上传的图片，未上传时延续最近参考图或最新生成图。提供给聊天模型的图片压缩到最长边 1536，生图仍使用原图。聊天请求超时或中断不会自动重发，用户可明确重新发送。服务端从已保存的最新方案取提示词、参数和参考图，同一方案重复确认会返回同一个生图任务。

对 POST 的超时或进程中断不自动重试，以免重复扣费。已拿到任务号的任务可以恢复 GET 轮询。超过 30 分钟未取回结果显示“需要核对”，可“检查进度”继续查询而不产生新生成请求。没有任务号的模糊提交须人工核对供应商记录。

生成结果从受信任的供应商存储域名下载，解码校验后保存在私有目录。已保存的历史不依赖供应商临时图片地址。图片读取/下载都会重新验证登录、模块权限和所有者。UI 删除采用软删除；不自动清理文件。

主要回归：`server/domains/design/designStudio.test.ts`，覆盖权限、工作空间及所有者范围、幂等、参考图授权、提交中断、轮询恢复、结果保存失败和 URL 边界。
